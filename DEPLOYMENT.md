# Deploying RP Car Showroom

**Stack:** Frontend → Vercel · Backend → Render · Database → MongoDB Atlas

Do these in order — each step needs the URL/value from the one before it.

---

## 1. Push to GitHub

```bash
cd rpcarshowroom
git init
git add .
git status
```

**Before committing**, check `git status` output — you should NOT see
`backend/.env`, `backend/node_modules/`, or `frontend/node_modules/` listed.
If you do, stop and check your `.gitignore` files before continuing.

```bash
git commit -m "Initial commit: RP Car Showroom"
git branch -M main
```

Create a new **empty** repo on GitHub (no README/gitignore/license — you
already have those), then:

```bash
git remote add origin https://github.com/YOUR_USERNAME/rpcarshowroom.git
git push -u origin main
```

---

## 2. MongoDB Atlas (database)

1. Go to [mongodb.com/atlas](https://mongodb.com/atlas) → create a free
   cluster (M0 tier).
2. **Database Access** → add a database user with a username/password.
3. **Network Access** → add IP `0.0.0.0/0` (allow from anywhere — Render's
   IPs aren't static on the free tier).
4. **Connect** → "Drivers" → copy the connection string. It looks like:
   ```
   mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/rpcarshowroom?retryWrites=true&w=majority
   ```
   Make sure to add `/rpcarshowroom` before the `?` so it targets the right
   database name. Save this — it's your `MONGODB_URI`.

---

## 3. Backend on Render

1. Go to [render.com](https://render.com) → **New** → **Web Service** →
   connect your GitHub repo.
2. Render should detect `render.yaml` at the repo root and pre-fill most
   settings (root directory `backend`, build `npm install`, start `npm
   start`). If it doesn't auto-detect, set those manually.
3. Under **Environment**, fill in the values `render.yaml` left blank:
   - `MONGODB_URI` — from step 2
   - `CLIENT_ORIGIN` — leave as `http://localhost:4200` for now; you'll
     update it after deploying the frontend in step 4
   - `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`,
     `ADMIN_EMAIL` — your email settings (see Gmail note below)
   - `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` — from
     [dashboard.razorpay.com/app/keys](https://dashboard.razorpay.com/app/keys)
     (use test keys until you're ready to go live)
   - `JWT_SECRET` is auto-generated by `render.yaml`; leave it
4. Click **Create Web Service**. Wait for the build/deploy to finish.
5. Once live, note your backend URL, e.g.:
   ```
   https://rpcarshowroom-backend.onrender.com
   ```
6. Test it: open `https://your-backend.onrender.com/api/health` in a
   browser — should return `{"status":"ok"}`.
7. Seed the database once, from your local machine, pointed at Atlas:
   ```bash
   cd backend
   # temporarily set MONGODB_URI in your local .env to the Atlas URI, then:
   node seed.js
   ```

**Gmail SMTP note:** use an App Password (Google Account → Security →
2-Step Verification → App Passwords), not your normal password.

**Free tier note:** Render's free web services spin down after inactivity
and take ~30-60s to wake up on the next request — expect a slow first
load after idle periods. Uploaded files (car photos, policy documents)
persist while the service is running but are wiped on redeploy/restart —
fine for testing, but plan to move to Cloudinary/S3 before treating this
as a permanent production catalog.

---

## 4. Frontend on Vercel

1. First, update `frontend/src/environments/environment.prod.ts` with your
   real Render backend URL from step 3:
   ```ts
   export const environment = {
     production: true,
     apiUrl: 'https://rpcarshowroom-backend.onrender.com/api',
     assetUrl: 'https://rpcarshowroom-backend.onrender.com',
   };
   ```
   Commit and push this change.

2. Go to [vercel.com](https://vercel.com) → **Add New** → **Project** →
   import your GitHub repo.
3. Set **Root Directory** to `frontend`.
4. Vercel should auto-detect Angular via `frontend/vercel.json`
   (build command `npm run build`, output `dist/frontend/browser`). If it
   doesn't, set those manually.
5. Click **Deploy**. Once live, note your frontend URL, e.g.:
   ```
   https://rpcarshowroom.vercel.app
   ```

---

## 5. Connect them — update CORS

Go back to your **Render** dashboard → the backend service → Environment
→ update `CLIENT_ORIGIN`:
```
CLIENT_ORIGIN=http://localhost:4200,https://rpcarshowroom.vercel.app
```
(comma-separated — this keeps local dev working too). Save — Render will
redeploy automatically.

---

## 6. Test the live site

1. Open your Vercel URL.
2. Register a new account, log in.
3. Log in as the seeded admin (`admin@rpcarshowroom.com` / `admin123`) and
   confirm the dashboard loads.
4. Try listing a car as the demo seller
   (`seller@rpcarshowroom.com` / `seller123`), approve it as admin, then
   book a test ride as the buyer account and confirm the email flow works
   (check the Render logs if SMTP isn't fully configured — emails will
   print there instead of sending).

If anything fails, open the browser DevTools → Network tab on the failing
request — a `0 B transferred` / `ERR_CONNECTION_REFUSED` means the backend
is down or asleep (wait ~60s and retry); a `401`/`403` is a real
auth/permissions issue; a CORS error in the Console means `CLIENT_ORIGIN`
on Render doesn't exactly match your Vercel URL.
